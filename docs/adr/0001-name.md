# ADR 0001: Name the project `mcp-cross-exam`

- **Status:** Accepted
- **Date:** 2026-10-26
- **Tracks:** A1 in #1

## Context

The spec called `mcp-audit` a working name. A1 requires the name to be free on PyPI, GitHub, and the Actions Marketplace before anything ships. `mcp-audit` is not free:

| Namespace | How it was checked | Result for `mcp-audit` |
|---|---|---|
| PyPI project | `https://pypi.org/pypi/mcp-audit/json` | 404, but see the next row. |
| PyPI near-match | Ultranormalized key `mcpaud1t` against the full index | Taken by `mcpaudit` 2.1.0. PyPI would reject a new upload as too similar. |
| Import package | Wheel contents | `mcp_audit/` ships in `mcp-audit-scanner` 0.21.1 and `mcp-server-audit` 0.1.1. |
| Console command | Wheel `entry_points.txt` | Both of those projects install `mcp-audit`. |
| Actions Marketplace | Listing | `mcp-audit` is listed by `adudley78/mcp-audit`. |
| npm | `https://registry.npmjs.org/mcp-audit` | `mcp-audit` 0.0.1 exists. |
| GitHub | Repositories | `adudley78/mcp-audit` is an active MCP security scanner. It owns the PyPI package, command, import package, and Action above. |

The import package collision is a problem even if the distribution is renamed. pip does not detect two distributions writing the same files. Installing this tool next to either project would silently overwrite one `mcp_audit/` package with the other. Both projects audit MCP servers, so they are likely to share a CI environment with this one.

PyPI's near-match rule is stricter than separator removal. Warehouse lowercases the name, maps `o` to `0` and `l` and `i` to `1`, and drops `-`, `_`, and `.`. It rejects a new project whose key matches an existing one. Two checks from the original A1 plan cannot detect this:

- TestPyPI has its own database, so a dry-run upload there says nothing about names on PyPI.
- Creating a pending trusted publisher on PyPI skips the near-match check today ([pypi/warehouse#16226](https://github.com/pypi/warehouse/issues/16226)). The rejection arrives at the first real upload.

This ADR replaces the TestPyPI dry-run with `tools/check_name.py`. The script computes each candidate's key and looks it up in the full PyPI index.

## Decision

The project is named **`mcp-cross-exam`**. The name describes the method: ask a server the same thing more than once, check its answers against its own schemas and descriptions, and keep the evidence. The tool questions the server and does not attack it, which fits the "Not a pentest" non-goal.

| Surface | Name |
|---|---|
| PyPI distribution | `mcp-cross-exam` |
| Import package | `mcp_cross_exam` |
| Console command | `mcp-cross-exam` |
| Action display name | `MCP Cross-Exam` (Marketplace slug `mcp-cross-exam`) |
| GitHub repository | `smusali/mcp-cross-exam` |

The distribution and the command share one name, so `pipx run mcp-cross-exam` and `uvx mcp-cross-exam` work without `--spec` or `--from`. There is no `mcp-audit` alias command. Two other projects already install that command, and uv refuses to overwrite an executable it did not install.

These names follow from it:

| Thing | Name |
|---|---|
| Config file | `mcp-cross-exam.toml`, or `[tool.mcp-cross-exam]` in `pyproject.toml` |
| Run directory | `.mcp-cross-exam/runs/<run-id>/` |
| Baseline file | `.mcp-cross-exam-baseline.json` |
| Tool snapshot | `mcp-cross-exam.tools.json` |
| Environment variables | `MCP_CROSS_EXAM_*`, for example `MCP_CROSS_EXAM_BEARER` |
| Action version input | `mcp_cross_exam_version` |
| Probe entry-point group | `mcp_cross_exam.probes` |
| `_meta` namespace | `io.github.smusali.mcp-cross-exam/` |
| SARIF fingerprint key | `mcpCrossExamFingerprint/v1` |
| SARIF category | `mcp-cross-exam` |
| PR comment marker | `<!-- mcp-cross-exam:summary -->` |
| Fix branch and trailer | `mcp-cross-exam/fix-<run8>`, `MCP-Cross-Exam-Fingerprint:` |
| Canary and marker prefix | `crossexam`, for example `crossexam.<run8>.<n>@canary.invalid`, `crossexam_tok_<run8>_<n>_<random>`, `crossexam_extra_<seed>` |

### Fallback

**`mcp-scrutineer`**. In motorsport, scrutineers inspect each car against the rules before it may race. It passed the same checks on the same date.

## Checks

Run on 2026-10-26 with `python tools/check_name.py`:

| Check | `mcp-cross-exam` | `mcp-scrutineer` |
|---|---|---|
| PyPI near-match | Key `mcpcr0ssexam`: free | Key `mcpscrut1neer`: free |
| PyPI project | Free (404) | Free (404) |
| TestPyPI project | Free (404) | Free (404) |
| npm package | Free (404) | Free (404) |
| Actions Marketplace slug | Not yet confirmed | Not yet confirmed |
| GitHub user or org | Not yet confirmed | Not yet confirmed |

The index held 923,857 PyPI projects. Registering `mcp-cross-exam` also blocks `mcp-crossexam` and `mcp_cross_exam` for anyone else, because they share a key.

The Marketplace and GitHub account rows could not run from the environment that wrote this ADR, because its network blocks github.com. Web searches the same day found no Action, package, or repository named `mcp-cross-exam`. A Marketplace Action name must not match an existing Action, a GitHub user or organization, or a Marketplace category. Re-run the script from a machine that can reach github.com before G4 (#7) publishes the Action. Both rows should read `free`.

PyPI does not index import packages or console commands, so those cannot be checked exhaustively. No PyPI project has a name near `mcp-cross-exam`, so no known distribution installs either one.

### Alternatives considered

| Name | Why not |
|---|---|
| `mcp-audit` | See Context. |
| `mcp-protocol-audit` | Free. However, 64 PyPI projects have names containing both "mcp" and "audit", and "protocol" suggests a spec-conformance tester like `@modelcontextprotocol/conformance`. |
| `mcp-polygraph` | polygraph.so already grades MCP servers with adversarial tests and evidence links. |
| `mcp-touchstone` | Touchstone is a conformance-testing platform with its own MCP server. |
| `checkride`, `mcp-checkride` | `checkride` on PyPI is an AI-agent security scanner. |
| `seatrials` | Free on PyPI and npm, but it suggests speed and endurance trials, which is close to the "Not a load tester" non-goal. |

## Consequences

- Every issue in the tracker uses these names from now on.
- Rename the repository from `smusali/mcp-audit` to `smusali/mcp-cross-exam` before G4 (#7) tags the first Action release. Workflows refer to an Action as `uses: owner/repo@ref`, so the repository path is the Action's identifier. GitHub redirects the old web and git URLs, but an Action's users should never depend on that redirect.
- The name is not claimed until the first upload to PyPI. Re-run `tools/check_name.py` before tagging the first release that publishes to PyPI (A7, #1). Do not upload an empty placeholder to reserve the name, because PEP 541 treats that as name squatting.
